Classify a math problem using only tags from the JSON below ("CANDIDATE TAGS").
The problem statement is provided in the user message. The tag names are in English. The format of
the JSON is as follows:

{[tag]: {"category": string, "description": string}}

where 'category' is the category of the tag, and the description is optional
(it can be an empty string). The meaning of categories is as follows:
- Area: Mathematical fields
- Goal: What is the problem asking of us?
- Type: What the problem is about. This is similar to the Area category, except it is
  more detailed. Acceptable use is to flag the use of a certain term / mathematical object
  in the problem statement.

CANDIDATE TAGS:
{candidate_tags}

Rules:
- Use ONLY candidate tags (exact spelling, case-insensitive match). Do not create new tags.
- Exactly 1 Area tag must be selected (approved) - prefer the most specific (e.g., "Combinatorial Geometry" not "Geometry" + "Combinatorics").
- Choose the Area from the problem's mathematical content and the nature of its goal, NOT from surface keywords. Integers or whole numbers appearing does NOT by itself mean "Number Theory" — reserve that for when divisibility, primes, gcd/lcm, modular arithmetic, perfect squares, or rationality is the crux. Real numbers, equations, inequalities, polynomials, functions, sequences, or optimizing/evaluating an expression point to "Algebra". A grid, table, or board is only a container: real-number entries that are optimized or bounded make the problem "Algebra", whereas discrete cells, colorings, tilings, or counting make it "Combinatorics". A counting or extremal goal ("how many", "largest possible") points to "Combinatorics" only when discrete configurations or arrangements are what is being counted; it does NOT override the content — counting or maximizing over integers governed by arithmetic conditions (differences, divisibility, gcd) can be "Number Theory".
- "Combinatorial Geometry" is mutually exclusive with "Geometry"/"3D Geometry". Use it ONLY when continuous-plane geometry is essential: points in convex or general position, convex hulls, distances or areas among points/figures, packings and coverings. A problem set on a square grid or lattice of discrete cells (lattice points, diagonals, colorings) is "Combinatorics", NOT this — the grid is a combinatorial structure and the geometry is only a backdrop; if it could be restated as a graph or array problem without losing its essence, it's "Combinatorics". Problems about lengths, angles, circles, or concyclic points are "Geometry"/"3D Geometry".
- Any number of Type tags may be approved, but they must be relevant.
- For most problems there should be exactly 1 approved Goal tag. Prefer the most specific Goal tag.
- Each tag must trivially follow from the problem statement, i.e., there must be no non-trivial inference. Otherwise, it could give away a part of the solution, which we want to avoid.
- If there are two tags from the same category such that one is more specific than the other, only the more specific tag should be used. (E.g., if the only purpose of
  a tag is that "another relevant tag is defined in terms of it", then it should be rejected.)

Output one entry per candidate tag, each with:
- "name": the tag name, exactly as given in the candidate list
- "goodnessOfFit": a real number between 0 and 1 (0 = no fit, 1 = perfect fit)
- "justification": a short reason for the score

Cover every candidate tag exactly once, and escape all TeX commands in strings — this is very important!
